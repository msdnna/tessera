# Changelog

All notable changes to Tessera are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/), versions per service.

## frontend

### [0.131.0] — 2026-07-13
- **Визуальные доработки:**
  1. Чипы composer bar и указатели (спринт/архив) — скругление 6px вместо
     «таблетки», чтобы повторять форму бара и кнопок.
  2. Автозаполнение браузера больше не подставляет логин/пароль в поля GitLab
     (URL/токен), OAuth-конфиг (secret/сервис-токен) и профиль (`autocomplete`-токены:
     `organization-title` для должности, `organization` и т.д.). Строка выбора
     привязки в модалке GitLab выровнена в ряд (dropdown + `＋`/`🗑` справа, с отступами).
  3. Меню «Показывать в дереве»: выбранный пункт помечается галочкой (без ●/○);
     «Показывать закрытые спринты» — чекбокс-иконка на месте значка (без ☑/☐ в тексте).
  4. Кнопка «Архив» в шапке подсвечивается как активная, пока открыт архив.
  5. Ручной выбор «Фильтр: этап» в composer сбрасывает выбранный в дереве спринт
     (кастомный мульти-фильтр важнее одиночного скоупа из дерева).

### [0.130.0] — 2026-07-13
- **Архив — доска только для чтения (вместо плоской модалки).** Кнопка «Архив»
  (десктоп и мобильное меню) теперь открывает саму доску в режиме `?archived=1`:
  архивные карточки в колонках со **всеми фильтрами/группировкой/сортировкой** доски
  (поиск, тег, исполнитель, приоритет, срок, этап). Амбер-чип «Архив (только чтение)»
  с крестиком выхода.
  - Карточки read-only: без DnD, инлайн-правок, контекст-меню и создания; вместо
    action-bar — кнопка «Вернуть из архива». Клик открывает задачу в **read-only
    TaskModal** (описание — превью, свойства display-only, без комментариев; в футере
    «Вернуть из архива»).
  - Старая `ArchiveModal.vue` удалена.

### [0.129.0] — 2026-07-13
- **Дедуп исполнителей в пикере:** GL-ростер на карточке больше не показывает людей,
  у которых уже есть Tessera-учётка (маппинг по `tessera_user_id`) — один человек
  не дублируется (учётка + строка GitLab).
- **Фильтр по GitLab-исполнителям:** в «Фильтр: исполнитель» добавлены GL-участники
  без Tessera-аккаунта (метка «… (GitLab)», значение `gl:<login>`); фильтрация идёт
  по `gitlab_assignee_logins`, чипы подписываются именем из GL.

### [0.128.1] — 2026-07-13
- **fix(GitLabModal): секция привязок доступна при системном сервис-токене.** Раньше
  «Привязки GitLab → доска» показывались только при подключённом личном PAT — при
  инстанс-токене (админка) в модалку было не попасть. Теперь секция видна, если задан
  сервис-токен ИЛИ подключён личный PAT; добавлена подсказка про системный токен;
  кнопки создания/правки/удаления привязок и «Сохранить» отключены для не-админа
  (просмотр и запуск синка остаются).

### [0.128.0] — 2026-07-12
- **Админка → GitLab OAuth:** добавлено поле **«Сервисный токен синка»** (PAT
  сервис-аккаунта) — под ним идёт весь синк, без личных токенов пользователей;
  плейсхолдер «сохранён», пустое значение не затирает. Подсказка разделяет две роли:
  OAuth-приложение = вход, сервисный токен = синхронизация; задачи мапятся по
  OAuth-идентичности. `admin.setOAuth` шлёт `service_token`.

### [0.127.0] — 2026-07-12
- **Навигация по спринтам в дереве проекта:** контекстное меню проекта →
  «Показывать в дереве» (Доски / Этапы / Доски и этапы) + «Показывать закрытые
  спринты» (localStorage). В режиме этапов под проектом рендерятся узлы-спринты
  (открытые сверху, свежие по дате) + «Бэклог»; клик открывает доску проекта,
  скоупленную по спринту (`?milestone=<id|backlog>`).
- **Скоуп-чип спринта на доске:** акцентный чип с названием активного спринта и
  крестиком; удаление возвращает полную доску и гасит подсветку узла. Активность
  узла выводится из URL-параметра (не «залипает»); группировка/сортировка/прочие
  фильтры доски сохраняются при переходе между спринтами. Смена спринта на той же
  доске догружает задачи серверно (без перемонтирования).
- Модалка задачи запрашивает issue-templates для «своей» привязки (`integration_id`).

### [0.126.0] — 2026-07-12
- **«Войти через GitLab»:** на экранах входа и регистрации — кнопка OAuth (видна,
  когда провайдер включён через `/auth/providers`); полностраничный редирект на
  `/api/auth/gitlab/authorize`. Новый роут `/oauth/callback` принимает сессию из
  URL-fragment (токены не попадают в логи), грузит профиль через `/auth/me` и
  чистит URL. Баннер ошибок OAuth на экране входа.
- **Админка → «Вход через GitLab (OAuth)»:** карточка настройки OAuth-приложения
  (URL GitLab, Application ID, Secret — «сохранён»-плейсхолдер, вкл/выкл, `org_map`
  JSON-редактор) + подсказка с Redirect URI. `admin.getOAuth`/`setOAuth`.

### [0.125.0] — 2026-07-12
- **Мультипривязка GitLab в модалке интеграции:** секция «Интеграция пространства»
  заменена на «Привязки GitLab → доска» со списком-селектором привязок
  (добавить/выбрать/удалить). У каждой привязки — имя, проект GL, доска, автосинк,
  источники дат, **что переносить** (все задачи / только назначенные) и **политика
  закрытых задач** (закрытые из закрытых спринтов → в архив / все на доску / за
  период с датой). Синхронизация и «создать issue» работают в разрезе выбранной
  привязки; журнал/конфликты — общие по пространству. Доска и модалка задачи
  определяют «свою» привязку по board_id.

### [0.124.3] — 2026-07-10
- **Ссылки на десктоп-сборки — относительные (отвязка от домена):** URL Windows/Linux
  строятся из имени файла в манифесте как `<serverBase>/desktop/<file>` (на web —

  в кнопках больше нет. Поддержан новый формат `downloads`-записей `{format, file}`
  (старый `{format, url}` тоже читается).

### [0.124.2] — 2026-07-10

### [0.124.0] — 2026-07-10
- **Кнопки скачивания приложений на экране входа (только web):** в шапке логина
  (слева от переключателя темы, скрыто внутри desktop-обёртки) — одна выпадающая
  кнопка «Скачать приложение». Иконка триггера = определённая платформа браузера
  (Windows / Linux / Android; детект по `navigator.userAgentData`/UA). В дропдауне —
  все доступные сборки, группами по платформам; текущая платформа идёт первой.
  Для Linux primary — **AppImage** (бейдж «рекоменд.»), рядом — `.deb` (и `.rpm`
  в будущем). Mac/iOS пока не предлагаем.
- **Корректность ссылок = рантайм-манифесты, без хардкода версий во фронте:** новый
  `useDownloads` читает `/apks/latest.json` и `/desktop/latest.json` (те же
  манифесты, что и self-update) и строит URL из них. Бамп Android/Desktop +
  републикация манифеста → ссылки автоматически валидны, пересборка фронта не нужна.
  Если манифест недоступен (dev-Vite без `/apks`) — кнопка просто скрыта.

### [0.123.0] — 2026-07-09
- **Канбан — доводка визуала колонок:**
  - **Тонирование фона колонок** цветом колонки (a reference tracker-style): тело колонки несёт
    очень лёгкий вош своего цвета (`color-mix ... 6%`, как на матрице); бесцветные
    колонки остаются нейтральными. Верхняя градиентная полоса без изменений.
  - **Свёрнутые колонки отдают ширину развёрнутым:** `colWidth` теперь делит доступную
    ширину только между развёрнутыми колонками, вычитая свёрнутые как 44px-полоски —
    место справа от свёрнутой колонки больше не пустует.
  - **Drag в свёрнутую колонку без раскрытия:** во время перетаскивания свёрнутая
    колонка остаётся полоской; бросок на неё добавляет задачу первым элементом сверху
    (drop-overlay на всю колонку + top-insert в `onColChange`).
  - **Различимые статус-иконки:** колонка «На рассмотрении» (и review/проверка/ревью
    по названию) получает иконку-глаз (`status-review-eye`) вместо общего pie —
    больше не путается с «В процессе».

### [0.122.1] — 2026-07-09
- **Полный фикс бага тегов в модалке** (0.122.0 чинил лишь частично): при цепочке
  A→B→A теги снова схлопывались в один чип + «+N». Причина — цикл обратной связи:
  замер читал ширину `inline-flex` кнопки-триггера, а она сжата до ширины уже
  свёрнутого содержимого. `useTagFit` теперь перед замером разворачивает все чипы
  (триггер дотягивается до реальной ширины контейнера), затем применяет fit, с
  guard от собственного resize — без осцилляции.

### [0.122.0] — 2026-07-09
- **Стек-поля — доводка:**
  - Срок в стеке пишется с заглавной буквы и полным названием дня недели («Суббота»,
    не «сб») — единообразно с остальными полями; в pill остаётся терсовый «сб»
    (`formatDue(..., { long })`).
  - Теги в стеке рисуются чипами-овалами с обводкой (как в модалке): сколько влезло
    в строку — то и показываем, остальное → «+N» (общий composable `useTagFit`).
  - **Фикс бага модалки:** при переоткрытии/переключении задачи теги показывались как
    один чип + «+N», хотя все помещались — `ResizeObserver` наблюдал старый
    (отмонтированный) элемент; теперь переобсервится при remount.
  - Аватары исполнителей снова накладываются друг на друга (flex-gap ломал каскад),
    выровнены по оси значений; белая обводка аватара красится в цвет фона строки
    (не «фонит» на hover).
  - Фикс строк-`<div>` (оценка/этап): были content-box → выше и hover уезжал за
    карточку; теперь `box-sizing:border-box`, единая высота и hover ровно по ширине.
- **Свой пак иконок** (`assets/view-icons`, в стиле ionicons 5) через новый компонент
  `TesseraIcon` (name + variant outline/sharp/filled, currentColor). Заменил иконки:
  - переключатель представлений в хедере (десктоп `BoardLayoutSwitch` + мобильное меню
    `BoardMobileMenu`): `layout-{kanban,list,calendar,timeline,gantt,matrix}`, активная
    вкладка — filled;
  - глифы статусов колонок канбана: `status-{todo,progress,done}`, плоский цвет колонки
    (убран прежний per-column SVG-градиент);
  - дефолтная иконка доски — `layout-kanban` (вместо самодельной/grid) в пикере, сайдбаре
    и flyout.
- **Иконка/цвет доски отражаются в дереве сайдбара** (`ProjectRow`): раньше у досок был
  статичный grid-глиф, не менявшийся при кастомизации — теперь рисуется своя иконка/цвет
  (как у проектов), дефолт — kanban, обновление вживую через `wsStore.upsertBoard`.
- **Компактные карточки сохраняют подзадачи** — в компактном виде, только название
  (без чекбокса, приоритета и срока). Пресет «Крупно» переименован в «Расширенно».
- **Стек-поля переработаны:** те же кликабельные триггеры, что и у pills (приоритет/
  срок/теги/исполнитель открывают свои пикеры), выложенные строками «иконка + значение».
  Цвет иконок сохраняется (приоритет, теги); теги рисуются цветным полукруглым чипом
  «+N», как в модалке; при наведении строка подсвечивается + подсказка с названием поля.
- **Панель доски:** название вынесено над выбором иконки; пикер иконки и палитра
  выровнены по левому краю; иконка/цвет доски теперь отражаются в дереве сайдбара.
- **Иконка доски по умолчанию — «канбан»** (собственный SVG-глиф в стиле ionicons,
  т.к. в ionicons5 нет kanban) вместо grid/инициалов.
- **Размер карточек теперь меняет компоновку, а не только шрифт:** «Компактно» —
  только название задачи (без pills/подзадач, колонка уже); «Средне» — название +
  #номер + приоритет/срок/теги + аватар исполнителя (как раньше); «Крупно» — все
  свойства (колонка шире). Ширина колонки привязана к размеру карточки.
- **Режим «Стек» переосмыслен:** вместо pills — строки «иконка поля + значение»
  (включая приоритет; без описания), значения выровнены по вертикальной оси; для
  неустановленных полей — прочерк. Уважает размер карточки и видимость полей.
- **Фикс: авто-сворачивание пустых колонок** не срабатывало, если колонку до этого
  разворачивали вручную (устаревший ручной override перебивал авто-правило) — теперь
  включение тумблера сбрасывает override у пустых колонок.
- **Иконка и цвет доски** (как у проектов/групп): в панели «Настроить вид» —
  IconColorPicker (набор иконок, палитра, режим бейдж/иконка) + переименование доски.
  Иконка доски показывается в списке досок сайдбара. Вся настройка доски — только в
  кастомизации.

### [0.118.0] — 2026-07-08
- **Сворачивание колонок канбана (a reference tracker-style):** у каждой колонки появилась кнопка
  свёртки (шеврон в заголовке) — свёрнутая колонка превращается в узкую вертикальную
  полосу с повёрнутым названием и счётчиком; клик по полосе разворачивает обратно.
  Состояние свёртки привязано к сохранённому представлению (и per-device localStorage).
  Переключатель «Сворачивать пустые колонки» авто-сворачивает колонки со счётчиком 0
  (явный разворот конкретной пустой колонки имеет приоритет над авто-правилом).
  Перетаскивание задач **в** свёрнутую колонку работает: на время перетаскивания все
  колонки временно раскрываются, поэтому drop-зоны, виртуализация и авто-скролл видят
  обычную геометрию; вытащить задачу из свёрнутой колонки нельзя (карточки скрыты).
- **Режим кастомизации доски («Настроить вид»):** кнопка подзадач на панели заменена
  шестерёнкой, открывающей правый сайдбар (`BoardCustomizePanel`). В нём: переименование
  доски; размер карточек (Компактно/Средне/Крупно — влияет на ширину колонки и плотность
  карточки через `--card-scale`); стек свойств (pills в столбик vs. в ряд); показ/скрытие
  пустых pills; пофайдовое скрытие pills на карточке (приоритет, срок, исполнитель, теги,
  оценка, этап, описание, #номер, GitLab); авто-свёртка пустых колонок; сводка и добавление
  группировки/сортировки/фильтра (переиспользует composer); переключатель раскрытия
  подзадач (перенесён сюда); автосохранение текущего представления. Все настройки
  привязаны к представлению; старые представления без новых ключей открываются с
  дефолтами (обратная совместимость).

### [0.61.0] — 2026-06-29
- **Механизм разрешения конфликтов write-back (фундамент, мигр. 0037).** Прежний loop-guard не замечал
  встречную правку в GitLab между синками → фактически last-writer-wins. Теперь у каждого линка есть
  **базлайн** `gitlab_links.gl_snapshot` (jsonb — последние синканные GL-значения), и при пуше
  `conflict`-проверяемых полей воркер делает трёхстороннее сравнение **base / theirs (текущее в GL) /
  ours (желаемое)**:
  - `theirs == ours` → уже синхронно, ничего не пушим;
  - `theirs == base` (или базлайна ещё нет) → чистая перезапись, пушим;
  - обе стороны ушли от базлайна → **конфликт**: строка outbox паркуется (`status='conflict'` +
    `conflict` jsonb с `{field, base, ours, theirs}`), пуш не выполняется, в журнал пишется action
    `op="conflict"`, по WS летит `gitlab.conflict`.
- **Интерактивное разрешение:** `GET /workspaces/:id/gitlab/conflicts` (инбокс открытых конфликтов) +
  `POST /tasks/:id/gitlab/conflicts/:conflictId/resolve` с `{resolution: ours|theirs|manual, value?}`.
  *theirs* — пишет GL-значение в задачу (без пуша); *ours* — признаёт текущее GL-значение базлайном и
  ре-арм пуша (воркер дольёт наше); *manual* — пишет присланное merged-значение в задачу и пушит его.
  При ре-арме воркер заново читает GL и при повторном расхождении безопасно ре-паркует.
- **Заморозка поля на pull:** пока по (task, kind) открыт конфликт, плановый pull не перезаписывает это
  поле задачи (по аналогии с `due_overridden`/`start_overridden`/`estimate_overridden`).
- **Объём этого прохода:** трёхсторонняя проверка включена для `due` и `estimate` (есть чистые
  per-field writer'ы). `state/priority/labels/assignees/comment` поведения не меняют (без регрессии);
  `title_desc` — следующим шагом. Снапшот пишется на pull (create/update линка) и после успешного пуша
  (`refreshLinkSnapshot`). Юнит-тесты на решающую функцию (`evalConflict`).
