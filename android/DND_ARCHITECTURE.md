# Drag-and-Drop на канбан-доске (Android / Jetpack Compose)

Документ описывает архитектуру DnD в Android-клиенте Tessera: перетаскивание
карточек, подзадач и колонок. Отдельно — ключевые отличия от `vue-draggable`,
который используется в веб-фронте, и грабли, на которые мы наступили.

> Файлы: `ui/components/BoardDrag.kt`, `ui/components/ColumnDrag.kt`,
> `ui/components/AnimatePlacement.kt`, `ui/components/TaskCard.kt`,
> `ui/screens/BoardViews.kt` (`KanbanView`), `ui/viewmodels/BoardViewModel.kt`.

---

## 1. Базовая идея

В вебе `vue-draggable` (обёртка над Sortable.js) делает почти всё сам: ловит
жесты, рендерит «клон» под курсором, сам анимирует и сам переставляет DOM-узлы,
а нам остаётся только обработать событие `@change`.

В Compose **нет готового кросс-контейнерного reorderable-примитива**, поэтому DnD
собран вручную из трёх слоёв:

1. **Жест** — `detectDragGesturesAfterLongPress` на нужном узле (тело карточки /
   подзадача / заголовок колонки). Долгое нажатие → старт, движение → обновление,
   отпускание → дроп.
2. **Состояние** — единый `BoardDragState` (Compose-`State`): что тащим, позиция
   пальца (в координатах окна), зарегистрированные bounds всех карточек/колонок.
3. **Разрешение дропа** (`resolveDrop` / `resolveColumnDrop`) — чистая функция:
   «палец вот тут, bounds такие → вставить туда-то». Результат используется И для
   подсветки места во время перетаскивания, И для самого действия при отпускании.

Само перемещение данных всегда идёт через бэкенд (`PATCH …/move`,
`PATCH …/parent`) и приходит обратно реактивно (reload + WebSocket). **Локального
оптимистичного переупорядочивания списка нет** — UI «как будто двигается» за счёт
ghost-копий, плейсхолдеров и анимаций, а реальный порядок меняется после ответа
сервера.

## 2. `BoardDragState` — единый источник правды

```
class BoardDragState {
    var dragging: Task?           // перетаскиваемая карточка/подзадача
    var draggingColumn: BoardColumn?  // перетаскиваемая колонка
    var pointer: Offset           // позиция пальца в координатах ОКНА
    var rootOffset: Offset        // позиция корня доски в окне (окно → локаль)
    var movedFar: Boolean         // палец сдвинулся дальше порога (24px)
    val cardBounds: Map<String, Rect>     // окно-bounds карточек/подзадач
    val columnBounds: Map<String, Rect>   // окно-bounds колонок
    val overlayTopLeft: Offset    // куда рисовать ghost (палец − захват − root)
}
```

- **Координаты — оконные** (`positionInWindow`), потому что ghost-оверлей и доска
  живут в разных поддеревьях; `rootOffset` переводит их в локальные.
- `cardBounds`/`columnBounds` регистрируются модификаторами `draggableCard` /
  `dropColumn` через `onGloballyPositioned` — это «глаза» функции разрешения дропа.
- `movedFar` — защита от ложного дропа: голый long-press (нажал-отпустил без
  движения) НЕ считается перетаскиванием (иначе подзадача «откреплялась» от
  простого зажатия).

## 3. Жесты: где висит `detectDragGesturesAfterLongPress`

| Что тащим            | Где висит жест                          | Файл           |
|----------------------|-----------------------------------------|----------------|
| Карточка (top-level) | **тело** карточки (header+pills)        | `TaskCard.kt`  |
| Подзадача            | каждая подзадача отдельно (row / карта) | `TaskCard.kt`  |
| Колонка              | **заголовок** колонки                   | `BoardViews.kt`|

Критично: родительский drag висит **только на теле карточки**, а НЕ на всём
контейнере (тело + подзадачи). Иначе два `detectDragGesturesAfterLongPress` в
одной точке (родитель и подзадача) дерутся за long-press, и жест срывается. Тело и
каждая подзадача — непересекающиеся зоны, каждая со своим жестом.

Тап и долгое нажатие сосуществуют: быстрый тап = открыть/переименовать, долгое =
drag (требует long-press-порога, поэтому не конфликтует с обычным скроллом).

## 4. Разрешение дропа

### Карточки/подзадачи — `BoardDragState.resolveDrop()`

Возвращает sealed-результат:

- `Drop.ToColumn(columnId, before, after)` — вставить как top-level карточку.
- `Drop.Nest(parentId, before, after)` — стать подзадачей родителя (на позицию
  между сиблингами; оба null = в конец).

Логика:

- **Перетаскиваем ПОДЗАДАЧУ** → резолв всегда только в reorder **внутри своего
  родителя** (никакого детача перетаскиванием — открепление только через модалку /
  контекстное меню, как на вебе).
- **Перетаскиваем top-level карточку**:
  - над телом другой карточки или её зоной подзадач → `Nest` (прикрепить);
  - над зазором в колонке → `ToColumn` (переместить / поменять колонку).

Действия в `BoardViewModel`: `dropTask` (если была подзадача — сначала detach,
потом move), `nestTask` (setParent при необходимости + позиция среди сиблингов
через `moveTask`).

### Колонки — `BoardDragState.resolveColumnDrop(orderedIds)`

Возвращает `(beforeId, afterId)` по `pointer.x` среди колонок. **Возвращает null,
если слот совпадает с текущим** (no-move) — тогда не рисуем линию и не дёргаем API.

## 5. «Живой» визуал

### Карточки (внутри обычного `Column` с `verticalScroll`)

- Перетаскиваемая карточка **схлопывается** на месте: `Modifier.dragCollapse(active)`
  = `graphicsLayer{alpha}` + `layout{ 0-высота }`. Узел остаётся в композиции
  (жест жив!), но слот сжимается.
- В точке посадки рисуется **полупрозрачная копия** карточки (`DraggedPreview`).
- Соседи разъезжаются через `Modifier.animatePlacement()` (onPlaced + `Animatable`
  по смещению).
- Под пальцем — ghost (`BoardDragOverlay`), для подзадач он подавлен (в маленьком
  списке только превью-строка + анимация).
- Переезд карточки в **другую** колонку → мягкое появление (`fadeInOnAppear`,
  alpha 0→1).

### Колонки (обычный `Row` с `horizontalScroll`, **НЕ LazyRow**)

- Оригинал остаётся на месте, **приглушённый** (`dragDim`) — без схлопывания, чтобы
  layout не прыгал.
- За пальцем едет **полноразмерный ghost-клон** (`ColumnGhost`: шапка + карточки)
  по `overlayTopLeft`.
- Вертикальная **линия вставки**: цвет = цвет перетаскиваемой колонки, фикс. отступ
  8dp сверху/снизу, по центру зазора (настоящий пиксельный midpoint между
  соседями; у края — по центру между крайней колонкой и краем доски).
- При дропе колонка плавно переезжает: `key(lane.id)` + `animatePlacement`.

### Автоскролл у краёв

`KanbanAutoScroll` — `LaunchedEffect`, который, пока идёт любой drag, двигает
горизонтальный `ScrollState`, если палец у левого/правого края экрана (зона 72dp).

## 6. Грабли, на которые наступили (и как решили)

1. **Удаление перетаскиваемого узла из композиции убивает жест.** Жест живёт на
   узле; если убрать карточку/колонку из дерева (например `if (id != dragged)` или
   фильтрацией списка), её `pointerInput` диспозится → drag срывается. **Решение:**
   никогда не убирать; вместо этого `dragCollapse` (0-высота/0-ширина, но узел
   остаётся).
2. **LazyRow рециклит off-screen элементы.** Перетаскивая широкую колонку к краю
   (с автоскроллом), исходная колонка уходит за экран → LazyRow её диспозит → drag
   срывается. **Решение:** колонки в обычном `Row(horizontalScroll)` (их мало).
3. **Структурное добавление/удаление модификатора `alpha` ломает отрисовку.**
   Условный `if (dragged) Modifier.alpha(…) else this` при дропе менял структуру
   нод и оставлял рамку/акцент карточки «непроявленными». **Решение:** модификатор
   применяется ВСЕГДА, меняются только параметры (`dragCollapse`, `dragDim`).
4. **`pointerInput(id)` захватывает устаревшее замыкание.** `pointerInput` намеренно
   переживает рекомпозицию (ключ стабилен), поэтому `onDrop`, замкнувший старый
   `lanes`/`state` (старый порядок колонок до переноса), не обновлялся → колонку
   нельзя было перетащить обратно после переноса. **Решение:** `rememberUpdatedState`
   внутри `composed{}` — pointerInput всегда читает свежее `onDrop`.
5. **`columnBounds`/`cardBounds` — в ПИКСЕЛЯХ.** Зазор `6f` оказался ~2dp, а не
   6dp. **Решение:** конвертировать dp через `toPx()`.
6. **Реактивность во время drag = дёрганье.** Пока тащим, прилетающие WS-обновления
   могут перетряхнуть доску. **Решение:** `vm.dragging`/`draggingColumn` ставят
   паузу на silent-reload, пока идёт перетаскивание.

## 7. Ключевые отличия от vue-draggable

| Аспект                | vue-draggable (web)                              | Наш Compose-DnD (Android)                                   |
|-----------------------|--------------------------------------------------|-------------------------------------------------------------|
| Готовность из коробки | Высокая: жесты, клон, анимация, перестановка DOM | Собрано вручную из жеста + состояния + резолва              |
| Перестановка          | Библиотека сама двигает DOM-узлы локально        | UI имитирует (ghost/preview/анимация), порядок меняет сервер |
| Клон под курсором     | Авто-клон элемента                               | Вручную: `BoardDragOverlay` / `ColumnGhost` по `overlayTopLeft` |
| Кросс-контейнер       | Через общие `group`                              | Своя `resolveDrop` решает колонку/родителя по координатам    |
| Рециклинг             | DOM не рециклится                                | LazyRow/LazyColumn рециклят → пришлось уходить на обычный Row |
| Реактивность во время drag | DOM не «перетряхивается» сервером           | Явная пауза reload (`dragging` флаг), иначе дёргает          |
| Lifecycle жеста       | Браузер не уничтожает перетаскиваемый узел        | Нельзя убирать узел из композиции — иначе жест умирает        |
| Анимация              | Встроенная (`animation` prop)                    | `animatePlacement` (slide) + `fadeInOnAppear` (появление)    |
| Вложение подзадач     | Sortable-группа + `.nest-zone`                   | `resolveDrop` различает «над телом / над зоной подзадач»     |
| Источник истины       | Часто локальный массив + emit                     | Только серверный порядок (REST move + WS), без optimistic    |

**Главная разница:** web получает «умный» компонент, который двигает DOM сам; на
Android мы строим DnD на низком уровне (жест → координаты → чистая функция резолва
→ серверное действие), а «живость» делаем оверлеями и анимациями поверх. Это даёт
полный контроль (подзадачи, вложение, confine-к-родителю, кастомные ghost/линии),
но требует ручного решения проблем, которых в DOM нет: рециклинг, lifecycle жеста,
устаревшие замыкания, px-vs-dp.
