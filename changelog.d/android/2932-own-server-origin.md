- **fix(android): «это наш сервер?» теперь сравнивается по origin, а не по началу строки (#2932).**
  Два места отвечали на этот вопрос как `url.startsWith(serverRoot)`, и оба ответа стоят
  сессии. `RichContent.shouldInterceptRequest` по такой проверке подставлял `Authorization:
  Bearer` — значит картинка `https://<наш-хост>.attacker.example/x.png` в описании задачи
  (обычный `![](…)`, DOMPurify его и не должен резать) уносила access-токен на чужой хост;
  вариант `https://<наш-хост>@attacker.example/x.png` проходил так же. В редакторе документов
  `shouldOverrideUrlLoading` по той же проверке оставлял навигацию **внутри** WebView, к
  которому подключён мост `AndroidDoc`, — а у него есть `requestToken()`, то есть чужая
  страница получала бы свежий токен в `window.tesseraEmbed.setToken`. Теперь оба зовут
  `isOwnServerUrl`: схема, хост и порт сверяются разбором того же парсера, которым пойдёт
  сам запрос (`okhttp3.HttpUrl`), а корень под путём владеет только своим поддеревом;
  что не разобралось — не наше (заголовок не ставим, ссылку отдаём браузеру).
  Разобрано тестами `ServerOriginTest`; негативный контроль — со старым `startsWith`
  шесть тестов из семи красные.
