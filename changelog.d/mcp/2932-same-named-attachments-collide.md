- **fix(mcp): два вложения с одинаковым именем скачивались одним файлом (#2932).** Имя
  вложения на задаче не уникально ничем: у `task_attachments` нет ограничения по
  `(task_id, filename)`, а `UploadAttachment` сохраняет `filepath.Base` того, что выбрали, —
  так что перезалитый после правки `screenshot.png` или один и тот же `log.txt`, снятый с
  двух машин, это две обычные строки. `tessera_download_attachment` же склеивал путь как
  `dest_dir/<имя>` и звал `os.Create`, который **усекает**: на диске оставался последний по
  порядку (`ListTaskAttachments` сортирует по `created_at`, то есть самый свежий), а в ответе
  по-прежнему перечислялись все вложения — один и тот же `path`, разные `id`, разные `size`.
  Читатель открывал «первый» файл и получал байты последнего, причём молча: ни ошибки, ни
  строки о том, что файл не тот, а `size` рядом с путём описывал файл, которого уже нигде
  нет. Для разбора «до/после» по двум одноимённым кадрам это ровно тот случай, когда сравнение
  сходится идеально — потому что сравнивается один файл с самим собой. Теперь имена
  разводятся в пределах одного вызова (`имя-2.png`), суффикс не накапливается между вызовами:
  повторное скачивание в тот же каталог обновляет файлы на месте. Вторая половина той же
  двусмысленности — выбор по `filename`: он отдавал **первое** совпадение, то есть самую
  старую версию, и просьба «дай `screenshot.png`» после перезалива возвращала ровно то, что
  заменили. Теперь возвращаются все строки с этим именем, каждая своим путём, — та же форма
  ответа, что и у ветки без селектора. Выбор по `attachment_id` по-прежнему называет ровно
  одну строку.
