- **fix(mcp): оценка задачи перестала быть «часами» — теперь это то же число, что хранит
  API (#2932).** Поле называлось `estimate_hours` и описывалось как «estimate in hours»,
  а значение уходило в `estimate` **без пересчёта**. Канон же у бэкенда другой: единица
  не свойство задачи, она берётся из двухуровневого конфига (переопределение проекта →
  умолчание пространства → встроенное time/8h/5d), и сам сервер «only validates and stores
  minutes» (`handlers/estimation.go`). То есть `estimate_hours=3` записывало **три минуты**
  вместо трёх часов — промах в шестьдесят раз, — а трёхчасовая задача читалась обратно как
  `estimate_hours: 180`. Ровно этот класс ошибки уже разобран и починен по соседству, в
  движке быстрых команд: `quickact.ParseEstimate` прямо пишет, что «/estimate 3» когда-то
  клало три минуты там, где поповер положил бы три часа, — «the same typing, off by sixty».
  На досках с `unit = points | custom` «часы» были не просто масштабированы неверно, а
  бессмысленны: канон там — число очков или штук, и quickact такой аргумент отбивает.
  Поле на входе и на выходе теперь одно — `estimate`, и его описание называет единицу.
  Пересчёт в MCP сознательно **не** делается: чтобы разрешить единицу, нужен проект задачи,
  а один путь чтения его не даёт — `tessera_my_tasks` собирает задачи из разных проектов, и
  в выдаче рабочего пространства есть `project_name`, но нет `project_id`. Конвертация
  вышла бы верной в списке доски и неверной в домашней очереди — это хуже одного честного
  числа. Человеческую длительность по-прежнему принимает `/estimate` в комментарии: она
  разрешает конфиг на сервере.
