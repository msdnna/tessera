- **fix(api): записанная GitLab-личность больше не пускает в учётку с другого
  инстанса (#2932).** «Continue with GitLab» находит учётку Tessera по числовому
  id пользователя GitLab, а этот номер — пер-инстансный: каждый GitLab выдаёт 1,
  2, 3… из своей последовательности, поэтому id 7 на одном сервере не имеет
  отношения к id 7 на другом. Именно для этого `oauth_identities` несёт колонку
  `gl_base_url` — но она только **писалась** при каждом входе (`upsertIdentity`)
  и **нигде не читалась**. Стоило перенаправить общую строку провайдера на другой
  GitLab (переезд с gitlab.com на self-hosted, восстановление, у которого id
  начались заново, случайно указанный стенд), и сохранённые номера продолжали
  совпадать: человек, которому на новом инстансе достался тот же номер, входил
  прямо в учётку, которую этот номер означал раньше, — сессия без пароля,
  впереди проверки адреса. Выходной `upsertIdentity` при этом перетирал
  `gl_base_url` новым значением, стирая единственный след. Теперь шаг «известная
  личность» требует совпадения инстанса; расхождение — не ошибка, а просто не
  совпадение: вход проваливается на этап сверки адреса, который и так строже
  (GitLab подтверждает адрес, а локальная учётка обязана была его доказать). Тот
  же инстанс под новым именем (`https://`, переименование в DNS) продолжает
  работать, потому что `CreateOAuthUser` заводит адрес уже подтверждённым.
