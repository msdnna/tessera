- **fix(api): «Разработка» задачи — MR и пайплайны из других проектов GitLab (#2964).**
  Привязка видела только MR своего проекта; теперь задача, зеркалящая issue, собирает все MR,
  которые GitLab связывает с issue (`related_merge_requests` + `closed_by`), из любых проектов,
  доступных токену, с последним пайплайном каждого (`head_pipeline` карточки MR). Тянутся в
  синке (изменившиеся issue, до 50 за прогон; MR с идущим пайплайном перечитываются) и при
  открытии задачи — в фоне, не чаще раза в 2 минуты, ответ приходит сокетом `task.code_links`.
  Проект без доступа (401/403/404) тихо пропускается. Ключ строки `task_code_links` теперь
  включает репозиторий (миграция 0095), в ответе — `ref` (`!12` своего проекта,
  `group/proj!12` чужого), в истории `code_change` — тоже `ref`.
