- **feat(api): GitLab — правила и конфликты (#3066).**
  Правило «лейбл → этап» (`action: milestone`, `template` «Спринт {value}» или карта значений):
  без нативной вехи issue задача встаёт в этап проекта с этим названием (создаётся при первой
  встрече, смена журналится); нативная веха GitLab важнее лейбла (#3086). Правило можно выключить
  (`disabled`), не удаляя; `POST /workspaces/:id/gitlab/rules/preview` считает задачи по каждому
  правилу и проверяет лейбл на правилах из формы (снапшот ссылки теперь хранит лейблы и исполнителей)
  (#3087). Политика конфликтов обратной записи `writeback.conflict_policy` ask | tessera | gitlab (#3088).
  Исполнители и лейблы-теги — поля конфликта; пакетное решение
  `POST /workspaces/:id/gitlab/conflicts/resolve`; поле с открытым конфликтом не перезаписывается пулом
  (#3089). Сверка запроса issue при обратной записи — без обсуждений. Полная сверка (#3105) дополнительно
  берёт обсуждения issue, тронутых за окно последней синхронизации (точность `updatedAt` — секунда).
