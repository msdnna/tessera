- **feat(gitlab): запись в GitLab от имени действующего пользователя (#2690).**
  Операции записи (создание issue, обратная запись, комментарии) больше не идут
  всегда под общим сервисным токеном. Порядок резолва креды на запись инвертирован:
  сначала личный PAT пользователя, затем — сервисный токен с заголовком
  `Sudo: <username>` (admin-имперсонация), затем — обычный сервисный токен / PAT
  владельца. Синхронизация (pull) по-прежнему идёт под сервисным токеном.
  В очереди writeback теперь хранится актор (`gitlab_writebacks.actor_user_id`), так
  что асинхронный push атрибутируется реальному пользователю. Sudo-имперсонация —
  явный переключатель админа (`oauth_providers.sudo_writeback`, по умолчанию выкл.):
  требует, чтобы сервисный токен был админским PAT со scope `api`+`sudo`; держать
  выключенным, если GitLab или Tessera доступны из внешней сети. Миграция `0052`
  аддитивная.
