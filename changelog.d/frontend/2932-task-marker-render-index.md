- **fix(web): галка в превью отмечает тот пункт, по которому кликнули (#2932).**
  Индекс, который присылает `RichContent`, — позиция отрисованного `<input>`, а
  `toggleTaskMarker` считала СТРОКИ исходника свободной регуляркой, и списки расходились
  в обе стороны: `- [ ] …` внутри ``` или отступного кода — это пример, чекбокса для него
  нет, а строка считалась; `> - [ ] …` в цитате чекбокс даёт, но строку регулярка не
  видела; `- [ ]x` без пробела GFM рисует текстом. В описании, где рядом с чек-листом
  лежит его же пример в блоке кода, клик по первому живому пункту переписывал строку
  ВНУТРИ блока кода, а сама галка отскакивала назад на ближайшей перерисовке.
  Теперь кандидат сверяется с лексером `marked`: правится та строка, после которой
  перерисовка отличается ровно нужным чекбоксом и ничем больше — оракулом стал тот же
  парсер, который эти чекбоксы и рисует.
