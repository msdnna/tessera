- **fix(web): список, перечитанный сразу после правки, мог вернуться без неё (#2932).**
  Одинаковые чтения справочников (теги, участники, вехи, колонки, префиксы тегов),
  отправленные одновременно, склеиваются в один запрос — доска открывает их все сразу.
  Но перечитывание списка ПОСЛЕ создания или удаления элемента тоже присоединялось к
  запросу, ушедшему на сервер ещё ДО правки, и получало ответ без неё: созданный тег не
  появлялся в пикере, приглашённый участник — в списке, и так до следующего обновления
  с другой стороны. Теперь любая запись помечает висящие чтения непригодными для склейки:
  следующий вызов открывает свой запрос, а уже начатые спокойно дочитывают своё.
