# Версии Tessera: продукт и компоненты

У Tessera два слоя версий. Они не спорят друг с другом, а отвечают на разные вопросы.

## Продукт — «Tessera 2.0»

То, что человек устанавливает и называет: **Tessera 2.0**, **Tessera 2.1**. Источник
истины — `release.json` в корне репозитория:

```json
{
  "product": "2.0.0",
  "name": "Tessera 2",
  "date": "2026-10-12",
  "components": {
    "backend": "0.112.0",
    "frontend": "0.190.0",
    "android": "0.77.0",
    "desktop": "0.4.1",
    "mcp": "0.6.0"
  }
}
```

- **MAJOR** — поколение продукта: новый интерфейс или бренд. «2» — редизайн v2.
- **MINOR** — релизный поезд: волна фич, выпущенная вместе (2.0 → 2.1 → 2.2).
- **PATCH** — исправления того же поезда (2.1 → 2.1.1).

В приложении продукт виден везде, где раньше была голая версия клиента: подсказка версии
у логотипа рейла («Tessera 2.0 · релиз от …», ниже — клиент и сервер), экран «Ещё», шапка и
раздел «Сервер» админки, «Что нового» (записи поезда подписаны «Tessera 2.0»). Админка
предупреждает, если сервер не из этого релиза — частичный деплой.

## Компоненты — semver

`backend`, `frontend`, `android`, `desktop`, `mcp` — у каждого свой `VERSION`, свой
`CHANGELOG`-раздел и свой релизный тег (`api/v…`, `web/v…`, `android/v…`, `desktop/v…`).
Это технический контракт: совместимость API и клиентов, self-update, образы в GHCR. Версии
компонентов **не синхронизируются** и **не поднимаются** ради продукта: редизайн не ломает
API — значит, это не повод для мажора `api`.

## Как выпускать

На `develop`, после слияния фич:

```bash
make changelog-release                 # 1. компоненты: VERSION + CHANGELOG из фрагментов
# whatsNew.js — запись про web-версию (скилл tessera-ship)
make release-product DRY=1             # 2. продукт: план
make release-product                   #    BUMP=minor по умолчанию; BUMP=patch|major, SET=X.Y.Z
git commit -m "chore(release): Tessera 2.1"
```

`make release-product` поднимает `release.json`, снимает текущие версии компонентов,
помечает записи «Что нового» этого поезда (`product: '2.1.0'`) и пишет заметки релиза
`docs/releases/v2.1.0.md`: пользовательские «Что нового» поезда и таблица компонентов
«было → стало».

Теги ставит человек:

```bash
git tag api/v0.113.0 && git tag web/v0.191.0      # компоненты, что изменились
git tag v2.1.0                                     # продукт
git push origin develop --tags
```

Тег `v2.1.0` запускает `.github/workflows/release-product.yml`: он сверяет тег с
`release.json` и версии компонентов с их `VERSION`, затем публикует GitHub Release
«Tessera 2.1» с заметками. Это «latest» релиз репозитория; компонентные релизы помечены
не-latest. Образы и приложения собирают компонентные workflow, продуктовый ничего не
собирает.

Первый релиз начал линию так: `make release-product SET=2.0.0 SINCE_WEB=0.186.0` — поезд
v2 начался с web 0.187.0 (редизайн).
