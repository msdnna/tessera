# ADR 0001 — Встроенный справочный центр (docs-as-code)

- **Статус:** принято (2026-08-21, задача #2786)
- **Контекст:** проект не документирован для пользователя.

## Решение

Пользовательская документация живёт **Markdown-файлами в репозитории** (`docs/help/`), а
приложение показывает их в собственном разделе «Помощь» (`/help/:slug?`), открываемом из
сайдбара: навигация по категориям, клиентский поиск и рабочая область статьи.

Контент собирается в индекс (`frontend/src/data/helpIndex.json`) на этапе сборки; тела
статей грузятся лениво, поэтому в основной бандл попадает только индекс. Рендер — уже
имеющийся `renderMarkdown` (marked + DOMPurify + highlight.js), новых зависимостей нет.
Бэкенд и миграции не нужны: справка read-only и едет вместе с бандлом, поэтому работает
офлайн и в desktop-сборке (Tauri).

## Почему так

- **Ревью и версионирование.** Статья правится тем же MR, что и код, который она описывает,
  и приезжает пользователю ровно с тем релизом, в котором фича появилась.
- **Ноль инфраструктуры.** Self-hosted инсталляции не надо ни сидировать контентом, ни
  деплоить рядом второй сайт.
- **Скриншоты автоматизируются.** Кадры снимает Playwright прямо в `docs/help/assets/`
  (см. #2789), пересъёмка после правок UI — одна команда, а не ручная работа.

## Отвергнутые альтернативы

**readthedocs / MkDocs / Docusaurus рядом.** Отдельный деплой и отдельный домен; справка
перестаёт быть частью приложения (нет контекстной помощи из экрана), а self-hosted
инсталляции получают ещё один сервис на обслуживание.

**Хранить статьи в модуле «Документы».** Контент уезжает из git: не ревьюится в MR, не
версионируется с релизом, каждую инсталляцию пришлось бы сидировать, всплывают права
доступа и мультиворкспейсность (у кого справка, если пространств несколько?). Модуль
«Документы» остаётся для пользовательского контента.

**Сгенерировать справку из CHANGELOG.** Changelog — для разработчика; пользователю нужен
сценарий («как перенести задачу»), а не список изменений.

## Следствия

- Правка справки требует пересборки фронта — приемлемо, релизы частые.
- Индекс `helpIndex.json` **генерируется** (`make help-index`) и лежит в git, чтобы сборка
  и тесты не зависели от порядка шагов; протухший индекс ловит `make lint-frontend`.
- Локализации нет: интерфейс и статьи — на русском, как и весь UI.
- Android (#2791) переиспользует те же `.md` и тот же индекс, а не заводит свой контент.
