A finished project doesn't have to be deleted. **Archiving a project** puts it out of sight — out of the project tree, search, My tasks and notifications — but keeps all of it: boards, tasks, stages, documents and history. The archive is reversible and has no time limit: the project stays there as long as you like.

## How to archive a project

- In the project's menu in the tree — **Archive** (the <kbd>E</kbd> key on a selected row).
- In the [Project](/help/project-window) window — the General tab, **Danger zone → Archive**.

The project goes to the archive at once, and a **Project “…” archived** message appears at the bottom with an **Undo** button (<kbd>Ctrl</kbd> <kbd>Z</kbd>). The workspace owner and admins can archive and restore projects.

## What changes for an archived project

- It is **not in the project tree**, in search and the palette, in My tasks or on Home.
- No **reminders or due-date notifications** arrive for its tasks, scheduled recurring tasks wait, and the automatic GitLab sync stops.
- Its boards open **view only**: cards don't drag, tasks aren't created or edited, and the task window shows a task for reading. The board bar carries an amber **Archived project** plaque.

## Where to find it and how to bring it back

At the foot of the project tree, while the workspace has archived projects, there is an **Archived projects** row with their count. Its menu lists every archived project with three actions:

- **Open · view only** — the project's first board;
- **Project settings** — the Project window;
- **Restore** — the project returns to the tree, and everything works as before.

You can also restore from the board itself — the **Restore** button on the Archived project plaque — and in the Project window, where Archive used to be.

## Archive and delete

**Delete project** is a different action: it can't be undone and erases the boards, tasks and stages. If a project is simply no longer in use, archive it rather than delete it.
