# tessera-orchestrate — волна задач

## 1. Разбор (координатор, до любых агентов)
- Очередь — `tessera_list_tasks` доски «Разработка» (`cd9efbd5-61ba-40d4-9696-1f6eb3d0fb77`,
  workspace `0cba7226-4501-4b06-a941-13d25defd8fd`). Ревью пользователя — комментарии
  `is_agent=false` (`/rework` = доработка; без комментария в «На рассмотрении» после его
  слов «принимаю» — закрывать). Сбор комментариев многих задач — дешёвому агенту (Sonnet)
  с требованием отдать человеческие комментарии дословно.
- **Пройтись по всем задачам волны поверхностно** (заголовок, описание, подзадачи) и
  сгруппировать по **общему контексту**: те же файлы/подсистема/таблицы → один исполнитель
  (или сам), а не два агента, читающих одно и то же.
- Классифицировать: **простое** (мелкий фикс, флейк, тест, правка текста) — делать самому, без
  агента; **сложное** (новая подсистема, миграция + UI, много файлов) — агенту **Opus**.
- Android (Kotlin) — deprecated: Android-подзадачи не брать.

## 2. Агенты
- Не больше **2** одновременно, `isolation: "worktree"`, фоново. Миграционные задачи — после
  безмиграционных; номер миграции агенту давать явно (следующий свободный в ветке слияния).
- **Бриф** (файл `/tmp/<волна>-briefs/<задача>.md`, промпт = «прочитай бриф»):
  1. `git reset --hard <базовый коммит>` первым шагом (worktree создаётся от `main`!);
     identity `msdnna` / `extracker0mail@gmail.com`; `corepack yarn install --immutable`
     (фолбэк — симлинк `node_modules` основного дерева);
  2. контекст: номер задачи (агент читает её через MCP), скилл `tessera-v2-ui` (+ раздел
     `areas.md`), макеты/кадры — готовыми PNG путями, не сервером;
  3. ресурсы: своя БД `tessera_test_<N>` (`TEST_DATABASE_URL`), свой бэкенд-бинарь/порт
     (`-o /tmp/tessera-e2e-bin-<N>`, :8093+), `TESSERA_PREVIEW_PORT` 4177+; **запрещены**
     `make e2e-backend-up/down` (общий бинарь, `fuser -k`) — общий :8092 поднимает координатор;
  4. проверки: только `make lint-<comp>` + **затронутые** тесты + **свои** e2e-спеки; полные
     прогоны, сканы, Android — НЕ запускать;
  5. conventional-коммиты после каждого шага, фрагмент `changelog.d/<comp>/<task>.md`,
     CLAUDE.md не править (строки — в отчёт), 1–2 скриншота максимум;
  6. отчёт ≤ 30 строк: коммиты, что сделано, что не проверено, строки для CLAUDE.md/areas.md.
- Лимит API (429) роняет всех сразу: worktree целы → `SendMessage` «продолжай, git status,
  коммить чаще». Упавший ДО первой правки — перезапускать новым Agent.

## 3. Слияние и гейты
- Ветка слияния `integration/<волна>` от develop; задачи вливать по одной (`merge --no-ff`
  или cherry-pick), после каждой — lint + затронутые тесты.
- Типовые конфликты: `featureStubs.js`, `shortcuts/catalog.js`, locales, `router.go`,
  `helpIndex.json` (пересобрать `node scripts/build-help-index.mjs`), `internal/db`
  (`~/go/bin/sqlc generate` заново), CSS-склейки теряют `}`, SQL-склейки дублируют JOIN.
  Храповик корзины ловит новые запросы соседей — дописать `deleted_at IS NULL`.
- Миграции подряд по порядку влития (`backend/e2e/migrate_test.go` ловит разрывы).
- Полные гейты — один раз в конце: `tools/integration-gates.sh` в фоне (сводка
  `/tmp/tessera-gates/summary`). `make scan-baseline-update` подхватывает gitleaks из
  `.claude/worktrees/agent-*` — секцию gitleaks возвращать из HEAD.
- Известные не-регрессии: `TestDockerImageBootsAndServes` (сеть docker в WSL).

## 4. Сдача и закрытие
- Задача → комментарий-отчёт (что, коммиты, как проверить, скриншот) → «На рассмотрении»,
  назначить `extracker0mail@gmail.com` (не `author` — у бот-задач автор = бот).
- Принятое: влить ветку слияния в develop → `make changelog-release` (скилл tessera-ship) →
  миграции на `tessera` и `tessera_test` → закрыть задачи (`tessera_move_task` «Готово»).
- Уборка: удалить worktree агентов, слитые ветки (`git branch --merged develop`), БД
  `tessera_test_<N>` (`docker exec tessera-postgres dropdb -U tessera <имя>`). Не пушить.
